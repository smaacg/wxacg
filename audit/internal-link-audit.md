# 內部連結與架構稽核 (Internal Link & Knowledge Graph Audit)

網站的內部連結不應該只是隨機的「相關文章」，而是要建立明確的「動漫知識圖譜 (Knowledge Graph)」。

## 1. 孤兒頁面 (Orphan Pages) 檢查
* **現狀**: 透過 Anime Sync Pro 匯入的大量動漫頁面，如果沒有被排入當季新番、首頁推薦，或是沒有關聯的新聞文章，很容易成為孤兒頁面。
* **風險**: 孤兒頁面缺乏內部權重傳遞，難以被 Google 爬蟲發現，也難以取得好的排名。
* **解法**: 必須確保每個動漫作品至少能透過「年份/季番」、「製作公司」、「分類標籤」等維度被找到。

## 2. 知識圖譜建構分析

目前的連結網絡較為單向，缺乏交叉連結。理想的架構應該如下：

### 動漫作品頁 (Anime) 為核心中樞
* **連出**: 
  * 製作公司 (已具備)
  * 參與角色、Staff (已具備)
  * OP/ED (應有獨立介面或連結)
  * 關聯的**新聞報導** (缺乏，需要補強)
* **連入**:
  * 從相關新聞文章連入 (非常重要，目前編輯常忽略手動插入連結)
  * 從角色頁面連回
  * 從「系列作 / 前作 / 續作」互相連結 (目前依賴 API，需加強 UI 顯示)

### 新聞文章 (News)
* **現狀**: 新聞文章常是獨立的孤島，看完就結束了。
* **解法**: 每篇與特定作品相關的新聞，**必須強制**加上該作品的內部連結卡片 (Anime Card)。這能把新聞的流量與權重導向資料庫頁面，提升資料庫頁面的 SEO 價值。

## 3. 分頁與導航 (Pagination & Breadcrumbs)
* **麵包屑 (Breadcrumbs)**: 必須確保 Schema 正確，路徑應為 `首頁 > 動漫 > {季番/分類} > {作品名稱}`，增強結構化資料的理解。
* **分頁**: 大量列表頁的深層分頁 (Page 5, 10, 50...) 會稀釋權重。強烈建議實作 `noindex, follow` 於第二頁以後的分頁。
